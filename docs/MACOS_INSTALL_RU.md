# Установка Daytrace на macOS без нотарификации Apple

Daytrace работает на macOS 12 и новее, на Mac с Apple Silicon и Intel. Текущая универсальная сборка распространяется без подписи Apple Developer ID и без нотарификации Apple, потому что у проекта пока нет этих учётных данных Apple.

Поэтому Gatekeeper может показать сообщение **«Apple не удалось проверить Daytrace на наличие вредоносного ПО»** или **«Невозможно открыть Daytrace, так как не удаётся проверить разработчика»**. Это предупреждение о доверии из-за отсутствия подписи Apple. Оно не означает, что macOS обнаружила вирус.

## Перед открытием файла

1. Скачайте DMG только с [официальной страницы релизов Daytrace](https://github.com/CaspianG/daytrace/releases/latest).
2. Скачайте `SHA256SUMS.txt` из того же релиза.
3. Откройте Terminal, выполните `shasum -a 256 ~/Downloads/Daytrace-*-macOS-universal.dmg` и сравните результат со строкой DMG в `SHA256SUMS.txt`.

Хеш должен совпасть полностью. Если он отличается, удалите скачанный файл.

## Установка и первый запуск

1. Откройте `Daytrace-…-macOS-universal.dmg`.
2. Перетащите **Daytrace** в **«Программы»**.
3. Откройте Finder и выберите **«Программы»**.
4. Нажмите **Daytrace** с удержанием Control или правой кнопкой мыши и выберите **«Открыть»**.
5. В окне подтверждения ещё раз нажмите **«Открыть»**.

Если macOS всё равно блокирует запуск:

1. Один раз попробуйте открыть Daytrace, чтобы macOS сохранила запись о блокировке.
2. Откройте **«Системные настройки» → «Конфиденциальность и безопасность»**.
3. Прокрутите до раздела **«Безопасность»** и найдите сообщение о блокировке Daytrace.
4. Нажмите **«Всё равно открыть»**, подтвердите действие паролем или Touch ID, если потребуется, затем нажмите **«Открыть»**.

Обычно это исключение требуется только при первом запуске конкретной скачанной сборки. Не отключайте Gatekeeper целиком и не вставляйте из интернета случайные команды для удаления quarantine-атрибутов.

## Включение локального сбора активности

После запуска самого приложения Daytrace покажет отдельную настройку «Универсального доступа». Разрешение нужно нативному локальному сборщику, чтобы видеть активное приложение и метаданные видимого активного окна. Оно не открывает облачный доступ и не связано с предупреждением Gatekeeper.

Нажмите **«Открыть настройки доступа»**, включите Daytrace в разделе **«Системные настройки» → «Конфиденциальность и безопасность» → «Универсальный доступ»** и вернитесь в приложение. Daytrace проверит нативный сборщик автоматически; при необходимости нажмите **«Проверить снова»**. Оставьте ровно одну установленную копию `/Applications/Daytrace.app`; при обновлении выбирайте **«Заменить»**, а не **«Сохранить обе»**, иначе macOS создаст `Daytrace 2.app` с отдельной записью разрешения. Можно продолжить без разрешения, но таймлайн останется пустым, пока доступ не выдан.

Если галочка уже включена, но Daytrace снова показывает экран разрешения:

1. В списке «Универсального доступа» выделите все старые записи **Daytrace** и **Daytrace 2** и удалите их кнопкой **«−»**.
2. Нажмите **«+»** и выберите именно `/Applications/Daytrace.app`, затем включите добавленную запись.
3. Вернитесь в приложение и нажмите **«Проверить снова»**. Daytrace проверяет разрешение тем же нативным сборщиком, который записывает события, поэтому обычный перезапуск больше не должен быть обязательным.
4. Если нужно сразу открыть интерфейс и разобраться позже, нажмите **«Открыть Daytrace без сбора»**. Это не блокирует настройки и локальные данные; сбор начнётся после выдачи разрешения.

В актуальной сборке нативный сборщик расположен внутри `Daytrace.app/Contents/MacOS` и относится к установленному приложению. Не выдавайте доступ копии, запущенной из DMG, папки «Загрузки» или файлу `Daytrace 2.app`: macOS хранит для таких копий отдельные записи.

## Обновления после установки

Начиная с v0.5.4 обычный сценарий — одна кнопка **«Настройки» → «Обновления» → «Обновить»**. Daytrace скачивает официальный универсальный DMG, проверяет SHA-256, подключает образ только для чтения, сверяет версию приложения внутри, заменяет `/Applications/Daytrace.app`, удаляет запущенный номерной дубликат вроде `Daytrace 2.app` и снова открывает Daytrace. Старая копия временно хранится для отката до успешного запуска новой. Finder открывается только тогда, когда macOS не разрешила автоматическую замену.

Начиная с v0.5.5 «успешный запуск» означает, что новое приложение действительно отрисовало и показало непустое окно, после чего вернуло защищённый одноразовый сигнал готовности. Успешной команды `open` теперь недостаточно. Если Gatekeeper блокирует новый bundle, renderer не загружается или сигнал не появляется за 90 секунд, Daytrace завершает эту копию, восстанавливает предыдущее приложение и автоматически открывает его. Локальный журнал результата находится в `~/Library/Logs/Daytrace/updater.log` и никогда не содержит историю активности.

Переход с v0.5.3 или более старой версии — одноразовое исключение: уже установленный файл умеет только открыть DMG, поэтому один раз выполните замену по инструкции выше. Начиная с v0.5.4 дальнейшие обновления проходят автоматически, а v0.5.5 добавляет безопасный откат с подтверждением реального запуска.

Поскольку текущая публичная сборка не имеет стабильной подписи Developer ID, после обновления macOS всё ещё может попросить повторно включить Daytrace в «Универсальном доступе». Daytrace обнаружит это и откроет нужный раздел настроек, но приложение не имеет права выдать себе защищённое системное разрешение.

## Почему предупреждение нельзя убрать программной настройкой

Для программ вне App Store Apple убирает такое предупреждение только после подписи платным сертификатом **Developer ID Application** и успешной проверки в сервисе нотарификации Apple. Самоподписанный или ad-hoc сертификат не создаёт такого доверия. В проекте сохранён строгий сценарий подписанного релиза на будущее, но текущие публичные macOS-артефакты честно обозначены как неподписанные и содержат эту инструкцию.
